### Что НЕ проверено на настоящем iPhone

Всё это сделано по правилам iOS и проверено только в эмуляции. Нужен прогон на устройстве (установленное приложение, не вкладка Safari):

1. Строка состояния в standalone (`apple-mobile-web-app-status-bar-style=default`) и верхний отступ под ней (safe area).
2. Буфер обмена: появляется ли системная плашка «Вставить» при `navigator.clipboard.readText()`; работает ли запасной путь (фокус в поле → «нажми и удерживай → Вставить»).
3. Выбор файлов: видны ли `.md`, `.txt`, `.json` в системном окне выбора; восстановление из файла, сохранённого в «Файлы».
4. Клавиатура в шторках (изменить книгу, заметка, «одно действие»): не закрывает ли она поле и кнопки.
5. «Не гасить экран» (Wake Lock): в установленных PWA на iOS зависит от версии системы.
6. Поделиться: экспорт `.md` и резервной копии через `navigator.share({files})` (системное «Поделиться» → «Файлы»/Telegram), запасное скачивание.
7. Прокрутка и восстановление позиции при инерционной прокрутке: запись не чаще раза в 300 мс; сохранение при `visibilitychange`/`pagehide`, если приложение смахнули сразу после чтения.
8. Safe area снизу (индикатор «Домой») у нижней панели вкладок, панели чтения и тостов; сдвиг тостов над плашкой прогресса.
9. Полка с `content-visibility: auto`: на iOS Safari нет нативной привязки прокрутки, нужно убедиться, что список не «прыгает» и «назад» возвращает на то же место.
10. Нажатие на абзац в читалке открывает панель «Отметить / Заметка / Копировать» (обработчик событий мог не срабатывать на `<p>`/`<li>` в iOS Safari; исправлено, но на устройстве не проверено).
11. Офлайн-перезагрузка, установка и обновление (тост «Доступно обновление · Обновить») в установленном приложении; `navigator.storage.persist()` на iOS.
12. На Android (если пригодится): «Поделиться → Kisr Library» (share target).

Команды (подробнее в `CLAUDE.md` и `README.md`):

```
npm run dev          # http://localhost:5173
npm test             # юнит-тесты
npm run typecheck
npm run build        # tsc --noEmit && vite build

Процесс, по которому всё делалось: **spec → план → задачи**. Новую фичу сначала описывают в `docs/spec.md` (или правят его), потом раскладывают на задачи в плане, потом делают по одной: тест, код, `npm test && npm run typecheck && npm run build`, коммит. Конвенции: TDD для `src/core`, `src/db`, `src/markdown`; цвета только из токенов `src/styles/tokens.css`; интерфейс по-русски на «ты»; в git файлы добавляются по имени (не `git add -A`); conventional commits; личные папки закреплены в `.gitignore` как `/migration/` и `/kisr-library/`, плюс маска `*backup*.json`.

## 4. Известные ограничения и решения

### Решения, принятые по ходу (отличия от первой редакции spec уже внесены в `docs/spec.md`)

- Ветка `feat/pwa-mvp` в основном рабочем дереве, без отдельного worktree: приватные папки должны быть видны тестам совместимости и миграции.
- Текст вообще без заголовков становится одной главой «Текст» (как в spec), а не «Вступление», как в старом приложении.
- Ключи блоков и позиции совместимы со старым приложением байт в байт (см. выше): трогать алгоритм нельзя.
- Исходный `- [x]` в книге галочку не ставит: по сохранённому состоянию не отличить «не трогал» от «снял».
- Метка «Новая» означает «добавлена пользователем за последние 3 дня и не открывалась»: перенесённые и восстановленные книги её не получают.
- Прокрутка экрана восстанавливается только при «назад» (шаг по истории). Новый переход, в том числе переключение вкладки, открывает экран сверху.
- «‹» в читалке возвращает на страницу книги: шагом назад, если пришли оттуда, иначе страница книги заменяет читалку. Для этого роутер хранит в `history.state` адрес экрана «откуда» (`kisrPrev`).
- Поиск ведёт в читалку по `#/read/:id/:chapter?find=<q>`: встаёт на первый блок с совпадением и подсвечивает его.
- Вторая вкладка оглавления называется «Отметки» (в первой редакции spec — «Отметки в книге»).
- На странице книги карточка «Одно действие» стоит над списком глав; в меню «⋯» есть ещё «Отметить прочитанной» / «Вернуть в «Читаю»».
- Санитайзер DOMPurify ужесточён: запрещены `style`, `form`, `button`, `select`, `textarea`, `iframe`, `object`, `embed` и атрибут `style`; `input` оставлен только для чекбоксов; `img`/`svg`/`video` разрешены. Импортированный текст не должен исполнять код.
- Для не последних частей книги (`part.n < part.of` или `of` неизвестно) предупреждение «Карточек нет» не показывается.
- Кэш поиска по тексту ключуется `id:contentHash`.
- Тесты на реальных данных пропускаются, если нет `migration/` и `kisr-library/` (так проходит CI); в тестах миграции чтение реальных данных вынесено в `beforeAll`, чтобы набор загружался и без приватных папок.

### Ограничения (известные, не критичные)

- **Импорт.** Текст после закрывающего ```` ``` ```` (например, «Хочешь, продолжу?») остаётся в конце последней главы и меняет хэш содержимого. «Дописать» к уже прочитанной книге оставляет её «Прочитано» (100%), даже если главы новые. Две части одной книги, вставленные разом, становятся двумя книгами. Одна и та же часть, вставленная дважды, допишется дважды.
- **Читалка.** Содержимое без ключей (таблицы, колода карточек) не может быть точным якорем: возобновление внутри длинной таблицы показывает её с начала. Одинаковые абзацы дают одинаковые ключи (используется первый). Строки в самом верху экрана могут оказаться под панелью после открытия, если панель была спрятана при сохранении. Короткая последняя глава может завершить книгу при открытии по ссылке или из оглавления. Нет выбора абзаца с клавиатуры. После закрытия шторки заметки фокус не возвращается на абзац.
- **Данные.** Запись сигналов оптимистична: при сбое IndexedDB состояние в памяти не откатывается. Редкие гонки: двойное нажатие на ★, отмена удаления ровно на границе 6 с. Проверка файла копии поверхностная: сильно повреждённый файл может упасть с ошибкой, а не с понятным сообщением. Скорость чтения из файла копии не проверяется на допустимый диапазон 120–300.
- **Полка и поиск.** Результаты по тексту идут в порядке ключей БД (глава 100 раньше главы 11), «Показать все» рисует всё сразу, раскрытое состояние не запоминается.
- **Зависимости.** `npm audit` показывает 4 замечания средней серьёзности в инструментах сборки (в приложение они не попадают).
- **Скилл.** Порог «длинной книги» (около 5000 слов) размыт; Claude не видит полку, поэтому разделы в разных чатах могут называться по-разному (в предпросмотре их можно поправить); ответ с несколькими книгами сразу может упереться в лимит вывода; утверждение «старый скилл заменится новым при загрузке» не проверено.
