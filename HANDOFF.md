## 1. Состояние

### Что сделано (по экранам)

- **Данные.** IndexedDB `kisr-library` (books, chapters, progress, marks, tasks, settings, inbox); сигналы в `src/state`, UI читает только их. Запись книги — одна транзакция; удаление — после окна отмены 6 с; «Обновить» сохраняет id, прогресс и отметки.
- **Парсер и формат.** `src/core/parse.ts` делит текст на главы так же, как `normalizeMd` старого приложения: мусор до шапки, обёртки ```` ```markdown ````, английские заголовки, длинные главы, части `part: N/M`, несколько книг в одной вставке. Слова `/[\p{L}\p{N}]+/gu`, 180 слов/мин, минуты `max(1, ceil(...))`.
- **Полка.** «Продолжить» (герой), «Читаю сейчас», сегменты статуса, разделы, сортировка, фильтр длины, шифры каталога, баннеры (резервная копия, установка на iOS).
- **Книга.** Главная кнопка, главы со статусами, теги, «одно действие», экспорт `.md`, правка названия/раздела/тегов, удаление с отменой.
- **Читалка.** Глава на одном экране, точное «где остановился» (ключ абзаца + запасной индекс + смещение), оглавление (главы и «Отметки»), «Aa» (размер, шрифт, интервал, тема, переносы, «Не гасить экран»), отметки и заметки к абзацам, чекбоксы, колода карточек, завершение книги и «одно действие», переход из поиска на совпадение.
- **Добавление.** Вставка из буфера, выбор файлов, предпросмотр, дубли (то же содержимое / то же название → «Обновить», «Дописать», «Отдельно»), восстановление из копии, конструктор запроса к Claude.
- **Поиск.** По названию, тегам, разделу, описанию и по тексту глав (со сниппетом и переходом к месту).
- **Перенос.** `npm run migrate` собирает `migration/kisr-library-backup-migrated.json`: 23 книги, 167 глав, 60 105 слов, 6 позиций чтения (в том числе «Дейл Карнеги» — глава 5). Это файл для «Ещё → Восстановить из копии».
- **Скилл Claude v2.** `claude-skill/kisr-library-razbor/SKILL.md`, zip для claude.ai и текст для Claude Project; формат проверяется тестом `claude-skill/skill-format.test.ts` на разборе шаблона.
- **Документы и выкладка.** `README.md`, этот файл, `.github/workflows/deploy.yml` (тесты → сборка с `BASE_PATH=/<репозиторий>/` → GitHub Pages).
- **Заметки и «Ещё».** «Заметки»: отметки и заметки по книгам и «Действия» из всех книг. «Ещё»: внешний вид, резервная копия и восстановление, напоминание о копии, статистика, справка.
- **PWA.** Манифест, иконки, service worker (вся сборка со шрифтами — в офлайн-кэше), тост «Доступно обновление · Обновить», share target на Android.
- **Сквозные тесты.** Playwright: вставка и чтение по главам; место чтения (прокрутка → перезагрузка, «Продолжить», смена размера шрифта); резервная копия (скачать → восстановить в чистом профиле → восстановить ещё раз); поиск по тексту; офлайн.
- **Надёжность (финальная волна исправлений).**
  - Если хранилище не открылось или молчит 8 с, приложение показывает экран «Не удалось открыть хранилище», а не пустую полку.
  - Если «заглянуть» по отметке, заметке или результату поиска, место чтения не сдвигается, пока ты сам не прокрутишь главу. Это держится и после перезагрузки (например, «Обновить» в тосте), и когда открыта шторка с клавиатурой.
  - Заметка, набранная в шторке, сохраняется, даже если закрыть шторку мимо «Сохранить».
  - Повторно вставленная часть книги, которая уже есть на полке, по умолчанию не сохраняется: «Эта часть уже в книге».
  - Книга в обёртке ```` ``` ```` больше не теряет главы после блока кода без языка.

### Что НЕ проверено на настоящем iPhone

Всё это сделано по правилам iOS и проверено только в эмуляции. Нужен прогон на устройстве (установленное приложение, не вкладка Safari):

1. Строка состояния в standalone (`apple-mobile-web-app-status-bar-style=default`) и верхний отступ под ней (safe area).
2. Буфер обмена: появляется ли системная плашка «Вставить» при `navigator.clipboard.readText()`; работает ли запасной путь (фокус в поле → «нажми и удерживай → Вставить»).
3. Выбор файлов: видны ли `.md`, `.txt`, `.json` в системном окне выбора; восстановление из файла, сохранённого в «Файлы».
4. Клавиатура в шторках (изменить книгу, заметка, «одно действие»): не закрывает ли она поле и кнопки.
5. «Не гасить экран» (Wake Lock): в установленных PWA на iOS зависит от версии системы.
6. Поделиться: экспорт `.md` и резервной копии через `navigator.share({files})` (системное «Поделиться» → «Файлы»/Telegram), запасное скачивание.
7. Прокрутка и восстановление позиции при инерционной прокрутке: запись не чаще раза в 300 мс; сохранение при `visibilitychange`/`pagehide`, если приложение смахнули сразу после чтения.
8. Safe area снизу (индикатор «Домой») у нижней панели вкладок, панели чтения и тостов; сдвиг тостов над плашкой прогресса.
9. Полка с `content-visibility: auto`: на iOS Safari нет нативной привязки прокрутки, нужно убедиться, что список не «прыгает» и «назад» возвращает на то же место.
10. Нажатие на абзац в читалке открывает панель «Отметить / Заметка / Копировать» (обработчик событий мог не срабатывать на `<p>`/`<li>` в iOS Safari; исправлено, но на устройстве не проверено).
11. Офлайн-перезагрузка, установка и обновление (тост «Доступно обновление · Обновить») в установленном приложении; `navigator.storage.persist()` на iOS.
12. На Android (если пригодится): «Поделиться → Kisr Library» (share target).
13. «Заглянуть» и клавиатура: открыть заметку из «Заметок» (в другой главе, не там, где «Продолжить»), изменить её, сохранить, вернуться на полку — «Продолжить» не должен измениться. Прокрутка, которую делает клавиатура iOS, не должна считаться твоей.

## 3. Как продолжить

Команды (подробнее в `CLAUDE.md` и `README.md`):

```
npm run dev          # http://localhost:5173
npm test             # юнит-тесты
npm run typecheck
npm run build        # tsc --noEmit && vite build
npm run preview      # собранная версия (service worker работает только здесь)
npm run e2e          # Playwright
npm run migrate      # migration/raw + kisr-library/ → migration/kisr-library-backup-migrated.json
npm run skill        # пересобрать zip скилла
npm run icons        # PNG-иконки из assets/icon.svg
```

Процесс, по которому всё делалось: **spec → план → задачи**. Новую фичу сначала описывают в `docs/spec.md` (или правят его), потом раскладывают на задачи в плане, потом делают по одной: тест, код, `npm test && npm run typecheck && npm run build`, коммит. Конвенции: TDD для `src/core`, `src/db`, `src/markdown`; цвета только из токенов `src/styles/tokens.css`; интерфейс по-русски на «ты»; в git файлы добавляются по имени (не `git add -A`); conventional commits; личные папки закреплены в `.gitignore` как `/migration/` и `/kisr-library/`, плюс маска `*backup*.json`.

Публикация (только с согласия владельца). История уже готова к публичному репозиторию:
- все коммиты — от `kisrxyz` с noreply-адресом GitHub, и локальная git-идентичность репозитория такая же;
- ссылка на старый артефакт и название города вычищены из всех коммитов.

Проверка перед push:
- `git log --format='%an <%ae>' | sort -u` — должен остаться один автор с noreply-адресом;
- `git ls-files | grep -iE "migration|kisr-library/|backup"` — должны быть только исходники (`src/core/backup.ts`, `src/db/backup.ts`, их тесты, `src/migration/*`, синтетические фикстуры).

Команды (Git Bash, из папки проекта; `gh` уже авторизован как `kisrxyz`):

```
git checkout main && git merge --ff-only feat/pwa-mvp
gh repo create kisrxyz/kisr-library --public --source . --remote origin
gh api -X POST repos/kisrxyz/kisr-library/pages -f build_type=workflow
git push -u origin main
gh run watch
```

`gh run watch` показывает выкладку по `.github/workflows/deploy.yml` (тесты → сборка → GitHub Pages), она идёт 2–3 минуты. Адрес приложения — `https://kisrxyz.github.io/kisr-library/`, он уже вписан в `README.md`.

Если включение Pages (`gh api … pages`) ответило ошибкой, сделай так:
1. Settings → Pages → Source: «GitHub Actions».
2. Перезапусти выкладку: `gh run rerun --failed`.

## 4. Известные ограничения и решения

### Решения, принятые по ходу (отличия от первой редакции spec уже внесены в `docs/spec.md`)

- Ветка `feat/pwa-mvp` в основном рабочем дереве, без отдельного worktree: приватные папки должны быть видны тестам совместимости и миграции.
- Текст вообще без заголовков становится одной главой «Текст» (как в spec), а не «Вступление», как в старом приложении.
- Ключи блоков и позиции совместимы со старым приложением байт в байт (см. выше): трогать алгоритм нельзя.
- Исходный `- [x]` в книге галочку не ставит: по сохранённому состоянию не отличить «не трогал» от «снял».
- Метка «Новая» означает «добавлена пользователем за последние 3 дня и не открывалась»: перенесённые и восстановленные книги её не получают.
- Прокрутка экрана восстанавливается только при «назад» (шаг по истории). Новый переход, в том числе переключение вкладки, открывает экран сверху.
- «‹» в читалке возвращает на страницу книги: шагом назад, если пришли оттуда, иначе страница книги заменяет читалку. Для этого роутер хранит в `history.state` адрес экрана «откуда» (`kisrPrev`).
- Поиск ведёт в читалку по `#/read/:id/:chapter?find=<q>`: встаёт на первый блок с совпадением и подсвечивает его.
- Вторая вкладка оглавления называется «Отметки» (в первой редакции spec — «Отметки в книге»).
- На странице книги карточка «Одно действие» стоит над списком глав; в меню «⋯» есть ещё «Отметить прочитанной» / «Вернуть в «Читаю»».
- Санитайзер DOMPurify ужесточён: запрещены `style`, `form`, `button`, `select`, `textarea`, `iframe`, `object`, `embed` и атрибут `style`; `input` оставлен только для чекбоксов; `img`/`svg`/`video` разрешены. Импортированный текст не должен исполнять код.
- Для не последних частей книги (`part.n < part.of` или `of` неизвестно) предупреждение «Карточек нет» не показывается.
- Кэш поиска по тексту ключуется `id:contentHash`.
- Тесты на реальных данных пропускаются, если нет `migration/` и `kisr-library/` (так проходит CI); в тестах миграции чтение реальных данных вынесено в `beforeAll`, чтобы набор загружался и без приватных папок.
- Если ты «заглянул» в другое место книги, место чтения не двигается. «Заглянуть» — это переход по отметке, заметке, результату поиска или по ссылке «Продолжить». Место запишется только после того, как ты сам прокрутишь главу. Переход к началу главы записывает место сразу: оглавление, «Дальше», «Предыдущая», первое открытие книги.
  - Пока ты только заглянул, `?b=`/`?find=` остаются в адресе. Поэтому перезагрузка или возврат по истории снова открывают то же место и ничего не записывают. Адрес очищает твоя первая прокрутка.
  - Прокрутка, пока открыта шторка, и ещё 0,7 с после неё (`SCROLL_SETTLE_MS`) считается прокруткой браузера: клавиатура, вернувшаяся полоса прокрутки. Сдвиг меньше 8 px (`PEEK_SLOP_PX`) тоже не заканчивает «заглянуть».
  - Конец главы, увиденный, пока ты только заглянул, не отмечает её прочитанной. Когда ты сам прокрутил, конец главы проверяется снова.
- Шторка заметки сохраняет набранный текст, даже если её закрыли мимо «Сохранить»: тапом по фону, Esc, ✕ или «назад» на Android. Если поле пустое, при закрытии ничего не происходит, и существующая заметка не удаляется.
- Часть книги (`part: N/M`), все главы которой уже есть на полке, по умолчанию не сохраняется: «Эта часть уже в книге». Если часть изменилась, приложение, как и раньше, предлагает «Обновить» или «Дописать».
- Как приложение находит конец книги в обёртке ```` ``` ````. Закрывающим считается только «пустой» забор, после которого до следующей книги или до конца текста нет ни заголовков, ни другого такого забора. Если после книги отброшено больше 30 слов, в предпросмотре появится предупреждение.
- Если хранилище не отвечает (ошибка или 8 с тишины), приложение показывает отдельный экран «Не удалось открыть хранилище» с кнопкой «Перезагрузить». Пустая полка с онбордингом появляется только тогда, когда база открылась и книг в ней 0.
- В названиях книг пробел перед « —» неразрывный, чтобы тире не уходило в начало строки. Это касается только интерфейса: текст глав не трогается, от него зависят ключи абзацев.
- В офлайн-кэш входят греческие подмножества шрифтов (символы в научных книгах), вьетнамские — нет.

### Ограничения (известные, не критичные)

- **Импорт.**
  - Текст после книги в обёртке ```` ``` ```` отбрасывается. Но если в этом «хвосте» есть свой блок кода, хвост может остаться в конце последней главы: текст не теряется, только лишний.
  - «Дописать» к уже прочитанной книге оставляет её «Прочитано» (100%), даже если главы новые.
  - Две части одной книги, вставленные разом, становятся двумя книгами.
- **Читалка.** Содержимое без ключей (таблицы, колода карточек) не может быть точным якорем: возобновление внутри длинной таблицы показывает её с начала. Одинаковые абзацы дают одинаковые ключи (используется первый). Строки в самом верху экрана могут оказаться под панелью после открытия, если панель была спрятана при сохранении. Короткая последняя глава, открытая из оглавления, может сразу завершить книгу; тост «Отменить» это откатывает. При переходе по ссылке такого уже нет. На Android привязка прокрутки браузера (например, когда дорисовался значок заметки) может закончить «заглянуть» так же, как твоя прокрутка; в Safari на iPhone такой привязки нет. В первые 0,7 с после закрытия шторки твоя быстрая прокрутка не учитывается: если сразу уйти, останется прежнее место. Нет выбора абзаца с клавиатуры. После закрытия шторки заметки фокус не возвращается на абзац.
- **Данные.** Запись сигналов оптимистична: при сбое IndexedDB состояние в памяти не откатывается. Редкие гонки: двойное нажатие на ★, отмена удаления ровно на границе 6 с. Проверка файла копии поверхностная: сильно повреждённый файл может упасть с ошибкой, а не с понятным сообщением. Скорость чтения из файла копии не проверяется на допустимый диапазон 120–300.
- **Полка и поиск.** Результаты по тексту идут в порядке ключей БД (глава 100 раньше главы 11), «Показать все» рисует всё сразу, раскрытое состояние не запоминается.
- **Зависимости.** `npm audit` показывает 4 замечания средней серьёзности в инструментах сборки (в приложение они не попадают).
- **Скилл.** Порог «длинной книги» (около 5000 слов) размыт; Claude не видит полку, поэтому разделы в разных чатах могут называться по-разному (в предпросмотре их можно поправить); ответ с несколькими книгами сразу может упереться в лимит вывода; утверждение «старый скилл заменится новым при загрузке» не проверено.
- **Мелочи из финального ревью, оставленные сознательно.**
  - «Ещё»: при каждом открытии на миг показывает «Готовлю копию…» вместо даты последней копии.
  - Копия пересобирается при любой смене настроек; на очень большой библиотеке это лишняя память.
  - Поиск: подсказка «Ещё одну букву» может на 150 мс отставать от ввода.
  - Поиск: пробел в конце запроса заново запускает поиск, и результаты мигают.
  - Android: книга, пришедшая через «Поделиться», теряется, если уйти с экрана «Добавить», не сохранив её.
  - Читалка: плашка прогресса в покое перекрывает последнюю строку и прячется при прокрутке.
  - `index.html`: переменная темы во встроенном скрипте глобальная (`var theme`).

## 5. Фаза 2 (spec §16)

Интервальное повторение карточек по всем книгам; список «Хочу прочитать»; синхронизация через приватный GitHub Gist; личная скорость чтения по `readingMs`; подборки и серии; чтение вслух (`speechSynthesis`); двухпанельный вид на ПК; статистика и серии дней. Для карточек понадобится повышение версии БД с новым хранилищем `cardStates` в `upgrade(db, oldVersion)`.
