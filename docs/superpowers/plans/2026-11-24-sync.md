# Синхронизация между устройствами — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** книги, места чтения, отметки, галочки и удаления сами сходятся на всех устройствах владельца через его приватный репозиторий на GitHub.

**Architecture:** чистое слияние и формат файлов — в `src/core/sync.ts`; хранилища `deleted` и `sync` (БД версии 2) и одна транзакция «прочитать — слить — записать» — в `src/db/sync.ts`; тонкий клиент Git Data API — `src/sync/github.ts`; один проход синхронизации — `src/sync/engine.ts`; расписание, сигналы и подключение — `src/state/sync.ts`; экран — `src/features/settings/SyncSection.tsx`.

**Tech Stack:** то, что уже есть (Preact, signals, idb, Vitest + fake-indexeddb + jsdom). `fetch` и `crypto.subtle` (SHA-1) браузера, без новых зависимостей.

**Spec:** `docs/spec.md` §18 (и §6 — модель данных).

## Global Constraints

- Всё из `CLAUDE.md` и плана MVP: интерфейс по-русски на «ты»; книги не в git; файлы в git по имени; TDD для `src/core`, `src/db`; после задачи `npm test && npm run typecheck && npm run build` зелёные, затем коммит с `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Ключ и `sync`/`deleted` никогда не попадают в резервную копию.
- В открытый репозиторий не пишем: `private !== true` → ошибка «Репозиторий открытый».
- Все запросы к API — `cache: 'no-store'`, заголовки `Authorization: Bearer <token>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`.
- Задержки: правки 3 с, место чтения 60 с тишины, повтор при временной ошибке 60 с, затем 300 с; до 3 попыток при «ref ушёл вперёд»; порция дерева ≤ 1 000 000 символов содержимого.
- Стартовый JS ≤ 120 КБ gzip.

## Review Focus

1. **Удалил книгу на телефоне, ноутбук был офлайн и потом синхронизировался** — книга пропадает и на ноутбуке, а не возвращается на телефон. Тест: задача 4, сценарий «удаление доезжает».
2. **Читаешь, пока идёт синхронизация** — свежая позиция не затирается более старой из репозитория. Тест: задача 2, `applyIncoming` не трогает прогресс, записанный новее входящего (слияние и запись в одной транзакции).
3. **Оба устройства синхронизируются по очереди без правок** — второй проход ничего не отправляет (нет «пилы» коммитов). Тест: задача 4, «повторный проход — 0 отправок» на обоих устройствах.
4. **Восстановил из копии книгу, которую раньше удалил** — после синхронизации книга остаётся. Тест: задача 2, `importBackup` снимает метку и ставит `updatedAt = now`.
5. **Ключ протух / репозиторий сделали открытым** — синхронизация останавливается с понятным текстом, данные на устройстве целы. Тест: задача 5, ошибки `auth` и `public` в `syncView`.

- [ ] Тесты (`src/core/sync.test.ts`): `canonicalJson({b:1,a:{d:2,c:[3]}}) === '{"a":{"c":[3],"d":2},"b":1}'`; `gitBlobSha('') === 'e69de29bb2d1d6434b8b29ae775ad8c2e48c5391'`, `gitBlobSha('привет\n')` совпадает с `git hash-object` (посчитать один раз и вписать); `bookPath('kak-rodilos-mwkko04g') === 'books/kak-rodilos-mwkko04g.json'`, у id с `/` или кириллицей путь из `[a-z0-9-]` и разный для разных id; `encodeBook`/`decodeBook` туда-обратно и `null` на мусор и чужой `format`; `encodeShared` одинаков при разном порядке записей.
- [ ] Тесты `planSync`: новая книга добавляется (`report.added`); более новая заменяет, старая пропускается; метка `book:` ≥ `updatedAt` удаляет локальную книгу и не пускает входящую; книга, правленная после метки, остаётся; прогресс — новее `lastReadAt`, ограничивается для укороченной книги, у удалённой книги отбрасывается; отметка с меткой удаления ≥ `updatedAt` уходит в `deleteMarks`; галочки — новее `updatedAt` целиком, без `updatedAt` — объединение; метки объединяются по максимуму и в `putDeleted` только изменившиеся; пустой `Incoming` даёт пустой план.
- [ ] Тесты `planPush`: книга без записи в `remote.books` или с более новым `updatedAt` — в `books`; книга из `remote.books`, которой нет локально и есть метка, — в `removeBooks`; общий файл — в `shared`, только если его sha отличается от `remote.files`.
- [ ] Реализация, тесты зелёные, коммит `feat(sync): file format and merge rules`.
