# Kisr Library (PWA) — спецификация

Версия 1 · 2026-11-22 · статус: утверждена к разработке (владелец сказал «просто начинай»; решения ниже — наши, их можно оспорить).

## 1. Зачем это

Kisr спрашивает Claude о темах, которые ему интересны, и получает ответ «книгой»: подробно, с реальными исследованиями и примерами, по главам. Книги копятся (сейчас 23, будут сотни), и их нужно читать с телефона в свободную минуту, возвращаться к месту, где остановился, и не теряться.

Сейчас это работает как артефакт в claude.ai (далее — **старое приложение**) плюс скилл `kisr-library-razbor`, который пишет разбор и сам кладёт его в базу артефакта. Владелец захотел настоящее приложение на телефон. Делаем **PWA**: оно открывается мгновенно, работает без интернета и стоит на экране «Домой» как обычное приложение.

**Цена решения, о которой владелец знает:** Claude больше не может сам класть книгу на полку. Книга попадает в приложение через «Добавить»: скопировал ответ Claude и вставил, или выбрал файл. Это должно занимать не больше 3–4 нажатий.

## 2. Цели, не-цели, анти-цели

**Цели (MVP)**
1. Полка на сотни книг, где сразу видно, что читаю, что новое и что прочитано, и легко найти нужное: разделы, поиск, сортировка, фильтр по длине.
2. Читалка с главами: точное «где остановился» (до абзаца), навигация по главам, время чтения (книга / глава / сколько осталось), настройки шрифта и темы.
3. Лёгкое добавление: вставка из буфера, выбор файлов (.md/.txt/.json), предпросмотр, защита от дублей, дописывание продолжения.
4. Перенос всех 23 книг и прогресса из старого приложения.
5. Работа офлайн, установка на iPhone и Android, резервная копия в файл и восстановление.
6. Обновлённый «скрипт» (скилл Claude), который выдаёт книгу в формате приложения, плюс конструктор запроса в самом приложении.
7. Отметки и заметки к абзацам, галочки в чек-листах, карточки для самопроверки, «одно действие» после прочтения.

**Не-цели (не делаем сейчас)**
- Сервер, аккаунты, синхронизация между устройствами (см. «Фаза 2»).
- Генерация книг внутри приложения через API (нужен платный ключ).
- Импорт EPUB/PDF/FB2.
- Соцфункции.

**Анти-цели (провал, даже если «работает»)**
- Потеря книг, прогресса или заметок.
- Медленный старт с сотнями книг (цель: полка видна меньше чем за 1 с на iPhone 12+).
- Добавлять книгу дольше и сложнее, чем 3–4 нажатия.
- Личные книги попадают в интернет: в публичный репозиторий, на хостинг или в чужой сервис.

## 3. Пользователь и контекст

- Один человек, пишет по-русски, читает в основном на **iPhone** (вероятно; Android тоже поддерживаем), иногда на ПК.
- Книги длиной 5–50 минут, чаще 10–30. Короткие (5 страниц) тоже бывают.
- Генерирует книги в claude.ai или в приложении Claude на телефоне.
- Интерфейс на русском, обращение на «ты» (как в старом приложении и в скилле).

## 4. Ограничения

- Только статический хостинг: GitHub Pages, публичный репозиторий с **кодом без книг**. Книги живут только на устройстве (IndexedDB) и в файлах резервных копий.
- Папка `migration/` (выгрузка старого приложения) и любые `*backup*.json` — в `.gitignore`. Никогда не коммитить.
- iOS: у PWA, установленной на экран «Домой», **отдельное хранилище**, не то, что у вкладки Safari. Значит, сначала нужно установить приложение и только потом добавлять книги. Приложение предупреждает об этом, когда открыто во вкладке браузера на iOS.
- iOS не поддерживает Web Share Target: «Поделиться → Kisr Library» работает только на Android. На iOS остаются буфер обмена и файлы.
- Совместимость с форматом скилла `kisr-library-razbor` (см. `docs/book-format.md`): любой разбор, который принимало старое приложение, принимает и новое.

## 5. Подход (как строим) и почему

Рассмотренные варианты:

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| A. Доработать артефакт в claude.ai | Claude сам кладёт книги, генерация внутри | Нужен вход в Claude и сеть; это не «приложение»; медленный старт | Нет: владелец явно хочет PWA |
| **B. PWA, данные на устройстве (IndexedDB), импорт вручную** | Быстро, офлайн, приватно, без сервера | Добавление — копировать и вставить | **Выбрано** |
| C. PWA + синхронизация через GitHub/Gist | Автодобавление, синхронизация устройств | Токены, сложность, риск утечки | Позже, фаза 2 |

**Стек (наше решение):** Vite + TypeScript + Preact + `@preact/signals`, `idb` для IndexedDB, `marked` + `DOMPurify` для Markdown, `vite-plugin-pwa` в режиме `injectManifest` со своим `src/sw.ts` (Workbox precache и обработка share target), Vitest + `fake-indexeddb` + `jsdom` для юнит-тестов, Playwright для e2e (WebKit/iPhone и Chromium/Android). Шрифты свои, без CDN: `@fontsource-variable/literata`, `@fontsource-variable/golos-text`, `@fontsource-variable/unbounded` (кириллица и латиница). Роутинг на `location.hash`, свой маленький роутер.

Почему так: Preact весит около 4 КБ и знаком любому, кто писал на React. На хеш-роутинге GitHub Pages работает без настройки сервера. IndexedDB легко держит сотни книг. Шрифты локальные, потому что офлайн они нужны.

## 6. Модель данных (IndexedDB `kisr-library`, версия 1)

Все времена — миллисекунды Unix. Хранилища:

```ts
// books — keyPath "id"; индексы: category, addedAt, updatedAt
interface BookMeta {
  id: string;            // slug(title, 40) + "-" + Date.now().toString(36); у перенесённых — старый id
  title: string;
  category: string;      // «Разное», если не задан
  tags: string[];
  summary: string;
  source: string;        // поле source из шапки
  level?: string;        // базовый | средний | продвинутый (необязательно)
  origin: 'paste' | 'file' | 'share' | 'backup' | 'migration';
  createdAt: number;     // когда книга создана (из старого приложения или = addedAt)
  addedAt: number;       // когда добавлена в это приложение
  updatedAt: number;
  words: number;
  cards: number;         // число пар Q/A
  tasks: number;         // число пунктов «- [ ]»
  chapters: { id: string; title: string; words: number }[];
  contentHash: string;   // hash() нормализованного полного текста — для дублей
  favorite: boolean;
  action?: { text: string; done: boolean; doneAt?: number }; // «одно действие» после прочтения
}

// chapters — keyPath "id" = `${bookId}--NN` (NN = 01, 02…); индекс bookId
interface Chapter { id: string; bookId: string; order: number /* с 1 */; title: string; md: string; words: number; }

// progress — keyPath "bookId". Нет записи = книга не начата.
interface Progress {
  bookId: string;
  chapter: number;        // текущая глава (order)
  blockKey: string | null;// ключ абзаца, где остановился (см. §8.3)
  blockIndex: number;     // запасной вариант: индекс якорного блока в главе
  blockOffset: number;    // 0..1 — насколько блок уже прокручен
  maxChapter: number;     // самая дальняя открытая глава
  chaptersDone: number[]; // главы, дочитанные до конца
  wordsRead: number;      // слов до текущей позиции (для % и «осталось»)
  percent: number;        // 0..100
  status: 'reading' | 'finished';
  startedAt: number; lastReadAt: number; finishedAt?: number;
  readingMs: number;      // активное время чтения (на будущее: своя скорость)
  snippet?: string;       // до 140 символов абзаца, где остановился
}

// marks — keyPath "id" = `${bookId}|${blockKey}`; индексы bookId, updatedAt
interface Mark { id: string; bookId: string; chapter: number; blockKey: string; text: string /* до 400 симв. */; highlight: boolean; note: string; createdAt: number; updatedAt: number; }

// tasks — keyPath "bookId"
interface TaskState { bookId: string; done: Record<string /* "t"+hash */, true>; }

// settings — keyPath "key"; значения: см. §10.7
interface Setting { key: string; value: unknown; }

// inbox — keyPath "id": временное хранилище для share target (Android) — SW кладёт, экран «Добавить» забирает
interface InboxItem { id: string; at: number; title?: string; text?: string; files?: { name: string; text: string }[]; }
```

При старте в память загружаются все `books` и все `progress` (это мало даже для 1000 книг). Главы читаются по требованию. Состояние хранится в сигналах (`src/state/*`). UI читает только сигналы, а запись идёт через функции `db/*`, которые сразу обновляют сигналы.

Будущие хранилища (`cardStates` для повторения карточек) добавляются повышением версии БД в `upgrade(db, oldVersion)`.

## 7. Формат книги и импорт

Полный контракт — в `docs/book-format.md`. Коротко: Markdown с YAML-подобной шапкой (`title`, `category`, `tags`, `summary`, `source`, необязательные `level` и `part`). Каждый `## ` — отдельная глава (экран). Текст до первого `##` — «Вступление». Чек-листы `- [ ]`, карточки в блоке ```` ```cards ````, таблицы GFM, цитаты `>`.

### 7.1 Парсер (`src/core/parse.ts`) — переносим 1:1 из старого приложения

Логика повторяет `normalizeMd` и связанные функции из `migration/old-artifact.html` (строки ~507–900: `cleanModelMd`, `parseFront`, `splitSections`, `HEADS`/`ruTitle`, `cleanSecMd`, `smartSummary`, `splitLong`, `normalizeMd`) и `pack.py` из старого скилла (`migration/old-skill-SKILL.md`). Цель — делить текст на главы **так же**, как старое приложение. Дополнительно:
- Мусор до шапки: если текст начинается не с `---`, но в первых 600 символах есть строка `---`, а за ней `title:`, всё до неё отбрасывается. Так работает копирование ответа вместе с вступительной фразой Claude.
- Поле `part`: `"2/3"` или `"2"` превращается в `{n: 2, of?: 3}`.
- Результат: `ParsedBook { title, category, tags, summary, source, level?, part?, chapters: {title, md}[], warnings: string[] }`. Предупреждения по-русски, например «Нет шапки: название взято из первой строки», «Нет глав (##): весь текст — одна глава», «Карточек нет».

### 7.2 Сценарий добавления (экран «Добавить»)
1. Источник: «Вставить из буфера» (`navigator.clipboard.readText()`; если не вышло — фокус в поле и подсказка «нажми и удерживай → Вставить»), поле для текста, «Выбрать файлы» (несколько; `.md`, `.markdown`, `.txt`, `.json`; на iOS не сужать `accept` до MIME — разрешить и `text/*`), и на Android — share target.
2. Определение типа: JSON с `"format": "kisr-library-backup"` → восстановление (§10.6). Иначе — Markdown-книга. В одной вставке может быть несколько книг: разделитель — новая шапка `---\ntitle:` в начале строки.
3. Предпросмотр каждой книги: название (можно править), раздел (выбор из существующих + «Новый раздел…»), теги, «N глав · ≈ M мин · K карточек», предупреждения, первые строки вступления.
4. Дубли:
   - тот же `contentHash` → «Эта книга уже на полке» и кнопка «Открыть»;
   - то же название (без регистра, ё=е, без пунктуации) → выбор: **Обновить** (id, прогресс и отметки сохраняются; глава прогресса ограничивается новым числом глав), **Дописать продолжением** (главы добавляются в конец; по умолчанию, если `part.n > 1`), **Добавить отдельно**.
5. «Сохранить на полку» (или «Сохранить все (N)»), затем тост «Книга на полке · Открыть». После первой сохранённой книги вызывается `navigator.storage.persist()`.

## 8. Читалка

### 8.1 Раскладка (телефон)
- Глава — один экран с вертикальной прокруткой. Пагинации нет.
- Верхняя панель: «‹» (к странице книги), название книги (одна строка) и «Глава 3 из 12», кнопки «Оглавление» и «Aa» (настройки). При прокрутке вниз панель прячется, при прокрутке вверх, у начала и у конца главы — появляется. Под панелью тонкая линия прогресса книги.
- Внизу, когда панель видна, — плашка «42% · ещё 14 мин».
- Конец главы: карточка «Дальше: <название> · 7 мин» (крупная) и маленькая ссылка «‹ Предыдущая глава». В последней главе — блок завершения (§8.5).
- На ПК клавиши ←/→ листают главы.
- Нижняя панель вкладок в читалке скрыта.

### 8.2 Рендер главы (`src/markdown/*`)
- `marked` (GFM, `breaks: false`), затем `DOMPurify` (разрешить `input[type=checkbox]`; сырой HTML из текста не исполнять).
- Пост-обработка (`enhance`) — как в старом приложении (`enhance()` в `old-artifact.html`, строки ~1421–1458): таблицы обёрнуты в горизонтальный скролл; ссылки с `target=_blank rel=noopener`; ```` ```cards ```` превращается в колоду (§8.6); пункты `- [ ]` — в настоящие чекбоксы с сохранением (§8.7); блокам выдаются ключи (§8.3).
- Типографика текста: Literata (или Golos в настройках), размер по умолчанию 18px (`1.125rem`), диапазон 15–24, межстрочный 1.6 (плотно 1.45 / свободно 1.75), `max-width: 65ch`, `hyphens: auto` при `lang="ru"` (отключается в настройках), `text-wrap: pretty` у абзацев и `balance` у заголовков. Заголовки `###` — Golos 600; название главы — крупнее, `text-wrap: balance`. Метки 🟢🟡🔴 остаются как есть.

### 8.3 Ключи блоков — совместимость со старым приложением
Алгоритм **ровно** как в старом приложении (иначе не найдутся перенесённые позиции):
```
hash(s): h = 5381; для каждого UTF-16 кода c: h = ((h << 5) + h + c) | 0; вернуть (h >>> 0).toString(36)
ownText(el): клон; удалить потомков ul, ol, .deck; textContent; /\s+/g → " "; trim
блоки: p, li, h3, h4, blockquote — кроме внутри .deck и кроме p, чей родитель li или blockquote; пропустить, если ownText короче 2 символов
key = первая буква tagName в нижнем регистре + hash(ownText)   // p…, l…, h…, b…
ключ задачи = "t" + hash(текст пункта, пробелы схлопнуты)
```
Якорные блоки для позиции — все элементы с `data-key` по порядку.

### 8.4 Позиция «где остановился»
- Сохранение: при прокрутке (не чаще раза в 300 мс), на `visibilitychange: hidden`, на `pagehide` и при уходе из читалки. Якорь — первый блок, чей низ ниже нижней границы верхней панели. Запоминаем `chapter`, `blockKey`, `blockIndex`, `blockOffset`, `snippet`, `wordsRead`, `percent`, `lastReadAt`.
- Переход по ссылке (`?b=` — заметка или «Продолжить», `?find=` — поиск, блок внутри открытой главы) место не перезаписывает: заглянуть в заметку — не значит потерять место, где остановился. Место пишется, только когда читатель сам прокрутил. Глава, открытая с начала (оглавление, «Дальше», «Предыдущая», первое открытие книги), записывается сразу.
  - Пока читатель только заглянул, `?b=`/`?find=` остаются в адресе: перезагрузка (например, «Обновить» из тоста об обновлении) или возврат по истории снова откроют то же место, ничего не записав. Адрес очищается его первой собственной прокруткой.
  - Прокрутка, пока страницу держит шторка, и 0,7 с после неё не считается прокруткой читателя: это клавиатура, вернувшаяся полоса прокрутки, привязка прокрутки. Сдвиг меньше 8 px подглядывание тоже не заканчивает.
  - Конец главы, увиденный при подглядывании, не отмечает её дочитанной; когда читатель сам прокрутил, конец главы проверяется снова.
- `wordsRead` = слова всех предыдущих глав + слова главы до якоря (накопленные суммы по блокам считаются один раз после рендера).
- Восстановление: отрисовать главу, дождаться `document.fonts.ready`, найти блок по ключу (если нет — по индексу), прокрутить к `top + offset·height` под панель и коротко подсветить блок (~2 с, без анимации при `prefers-reduced-motion`).
- Глава засчитывается дочитанной, когда в кадре виден конец главы (IntersectionObserver на «стражнике» в конце).
- Активное время чтения копится, пока вкладка видима и прокрутка была в последние 60 с.

### 8.5 Завершение книги
- «Служебные» главы — `Источники`, `Литература`, `Карточки`. Для завершения их дочитывать не нужно.
- Когда виден конец последней не-служебной главы, книга получает статус `finished` и тост «Книга в «Прочитано» · Отменить».
- Блок завершения, как в старом приложении: «Дочитал?», поле «Одно действие, которое сделаешь после книги» и кнопки «Сохранить» и «Вернуть в «Читаю»». Действие видно на странице книги и во вкладке «Действия» на экране «Заметки».

### 8.6 Карточки (колода)
Как в старом приложении (`buildDeck`): карточка «Вопрос → нажми → Ответ», «Назад/Дальше», счётчик «3 / 14», перемешать, показать списком. Парсер `parseCards` (Q/В/Вопрос, A/О/Ответ, многострочные значения).

### 8.7 Чек-листы
Пункты `- [ ]` / `- [x]` становятся настоящими чекбоксами (≥ 44px зона нажатия). Состояние хранится в `tasks[bookId].done[key]`. Исходный `[x]` в тексте галочку заранее не ставит: по сохранённому состоянию не отличить «не трогал» от «снял» (старое приложение вело себя так же).

### 8.8 Отметки и заметки к абзацу
- Нажатие на блок (не на ссылку, чекбокс, колоду или таблицу) выделяет его, и снизу появляется панель: «Отметить» (вкл/выкл), «Заметка», «Копировать», «Закрыть». Нажатие мимо закрывает панель.
- Отмеченный блок подсвечен латунным цветом (`--brass-soft` и полоса слева), блок с заметкой — с меткой «заметка».
- Шторку заметки закрыли мимо «Сохранить» (✕, нажатие мимо, Esc, «назад»): новый непустой текст сохраняется, и когда шторка уехала — тост «Заметка сохранена». Пустое поле при закрытии заметку не удаляет: для этого «Удалить заметку».
- Текст остаётся выделяемым системно (для копирования), `user-select` не трогаем.

### 8.9 Оглавление (шторка)
Список глав: номер, название, минуты, статус (✓ дочитана, ● текущая, ○ нет). Заголовки вида `N.M.` чуть сдвинуты вправо. Вторая вкладка шторки — «Отметки» (отмеченные блоки и заметки этой книги).

### 8.10 Настройки «Aa» (шторка)
Размер (A− / значение / A+), шрифт (С засечками / Без засечек), интервал (Плотно / Обычно / Свободно), тема (Авто / Светлая / Бумага / Тёмная), переносы (вкл/выкл), «Не гасить экран» (Wake Lock, если поддерживается). Применяются сразу и сохраняются в `settings`.

## 9. Время чтения
- Слова: `/[\p{L}\p{N}]+/gu` (как в старом приложении и `pack.py`).
- Скорость по умолчанию — 180 слов/мин (так считали старое приложение и скилл), в настройках от 120 до 300.
- Минуты: `max(1, ceil(words / wpm))`. Показываем «≈ 25 мин» у книги, «7 мин» у главы, «ещё 14 мин» в процессе чтения.
- Длина для фильтра: «до 10 мин», «10–30 мин», «30+ мин».

## 10. Экраны и навигация

Нижняя панель вкладок (скрыта в читалке): **Полка · Поиск · Добавить · Заметки · Ещё**. Маршруты (hash):

| Маршрут | Экран |
|---|---|
| `#/` (+ `?status=&cat=&len=&sort=`) | Полка |
| `#/book/:id` | Книга |
| `#/read/:id/:chapter` (+ `?b=<blockKey>`) | Читалка |
| `#/search?q=` | Поиск |
| `#/add` (+ `?shared=1`) | Добавить |
| `#/notes?tab=marks|actions` | Заметки |
| `#/settings` | Ещё |

Положение прокрутки каждого экрана запоминается и восстанавливается **только при «назад»** (шаг по истории). Новый переход, в том числе по вкладке нижней панели, открывает экран сверху. В режиме standalone на iOS нет кнопки «назад» браузера, поэтому у каждого вложенного экрана есть своя «‹». «‹» в читалке ведёт на страницу книги: шагом назад, если пришли оттуда, иначе страница книги встаёт на место читалки (без лишней записи в истории).

### 10.1 Полка
- Шапка: знак «Kisr Library» и кнопка «+» (→ Добавить).
- **Продолжить** (герой): последняя незаконченная книга — название, «Глава 3 · <название главы>», цитата места, где остановился (`snippet`, 2 строки, Literata), полоса прогресса, «42% · ещё 14 мин». Нажатие открывает читалку ровно на этом месте.
- **Читаю сейчас**: остальные начатые книги (до 5, по `lastReadAt`) компактными строками с прогрессом, плюс «Все (N)».
- Сегменты статуса: «Все · Читаю · Новые · Прочитано · ★» с числами.
- Фишки разделов с числами (горизонтальная прокрутка; если разделов больше 12 — «Все разделы…» в шторке).
- Строка «Сортировка» (Недавние — по умолчанию: max(lastReadAt, addedAt) / Добавлены / Название / Короче / Длиннее) и фильтр длины.
- Карточки книг в стиле библиотечного каталога из старого приложения: шифр «ФИЛ·03» + раздел, название (Literata 600), описание в 2 строки, «≈ 25 мин · 12 глав», полоса прогресса для начатых, «✓ Прочитано 17 нояб.» для прочитанных, ★ для избранных, метка «Новая» для добавленных за последние 3 дня и не открытых. `content-visibility: auto` для длинных списков.
- Шифр = первые 3 буквы раздела в верхнем регистре + номер по порядку `createdAt` в разделе (`callNumbers()` старого приложения).
- Пустая полка: короткий онбординг («1. Попроси Claude… 2. Скопируй… 3. Нажми «Добавить»») и кнопка «Добавить книгу».
- Баннер резервной копии (§10.6), если пора.
- На iOS в браузере (не standalone) — баннер «Установи на экран «Домой»: книги из браузера не попадут в приложение».

### 10.2 Книга
- «‹ Полка», ★, «⋯» (Изменить название/раздел/теги · Экспорт .md · «Отметить прочитанной» / «Вернуть в «Читаю»» · Удалить).
- Шифр и раздел, название, описание, строка «≈ 25 мин · 12 глав · 14 карточек · добавлена 17 нояб.».
- Главная кнопка: «Начать читать» / «Продолжить · гл. 3, 42%» / «Читать заново» (у прочитанной) + полоса прогресса.
- Список глав (как в оглавлении) с минутами и статусами; нажатие открывает главу.
- Теги-фишки (нажатие → поиск по тегу), источники (`source`).
- Карточка «Прочитано 17 нояб.» и «одно действие» (если книга прочитана или действие записано) стоит **над** списком глав, сразу под главной кнопкой: так она видна без прокрутки.
- Удаление: подтверждение в шторке, затем тост «Удалено · Вернуть» (отмена в течение 6 с; само удаление выполняется после таймаута или при уходе со страницы).

### 10.3 Поиск
- Поле в фокусе, `enterkeyhint="search"`; нормализация: нижний регистр, ё→е, без Markdown-разметки.
- Группа «Книги»: совпадения в названии, тегах, разделе, описании.
- Группа «В тексте»: совпадения в главах со сниппетом ±60 символов, где найденное подсвечено (`<mark>`), с названием книги и главы. Нажатие открывает читалку по ссылке `#/read/:id/:chapter?find=<q>`: она встаёт на первый блок главы, где есть совпадение, и подсвечивает найденное (`<mark>`).
- Тексты глав загружаются в память при первом поиске, дальше кэшируются. Ввод обрабатывается с задержкой 150 мс.

### 10.4 Добавить
Сценарий из §7.2, а под ним — **«Попросить Claude»**: тема, объём (Коротко ≈5 мин / Средне ≈15 / Подробно ≈30 / Книга 45+), пожелания, переключатель «Скилл установлен в Claude» (вкл: короткий запрос «Разбор для Kisr Library: …»; выкл: запрос плюс полный блок формата из `book-format.md`). Кнопки «Скопировать запрос» и «Открыть Claude» (`https://claude.ai/new?q=<encodeURIComponent>`; если адрес длиннее 6000 символов — только копирование). Ниже ссылка «Как это работает» с трёхшаговой инструкцией.

### 10.5 Заметки
Вкладки «Отметки» (отмеченные блоки и заметки, сгруппированы по книгам, новые сверху; нажатие → читалка на блоке) и «Действия» (одно действие из каждой прочитанной книги, с галочкой «сделано»). Пустые состояния объясняют, как появляются отметки.

### 10.6 Резервная копия и восстановление (в «Ещё»)
- Формат файла:
  ```json
  { "format": "kisr-library-backup", "version": 1, "exportedAt": 0, "app": "kisr-library@x.y.z",
    "books": [ { ...BookMeta, "chapters": [ { "title": "", "md": "" } ] } ],
    "progress": [], "marks": [], "tasks": [], "settings": {} }
  ```
- Экспорт: `kisr-library-backup-YYYY-MM-DD.json` через `navigator.share({files})`, где это доступно (на iOS открывается системное «Поделиться» → Файлы/Telegram), иначе через скачивание. Сохраняется `lastBackupAt`.
- Восстановление — слияние: книги по `id` (побеждает новее `updatedAt`), прогресс (новее `lastReadAt`), отметки (новее `updatedAt`), задачи (объединение), настройки (только если у нас пусто). После восстановления показывается итог «Добавлено 23, обновлено 0, пропущено 0».
- Напоминание на полке, если с последней копии добавлено 5+ книг или прошло 14+ дней и книг больше 0. Его можно скрыть на 7 дней.
- Экспорт одной книги в `.md` — обратная сборка (шапка + главы, как `reassemble()` в старом приложении).

### 10.7 Ещё (настройки)
- Внешний вид: тема, шрифт, размер, интервал, переносы, «Не гасить экран».
- Чтение: скорость (слов/мин) с подсказкой «время у книг пересчитается».
- Данные: резервная копия, восстановление, «Занято: 3,2 МБ» (`navigator.storage.estimate()`), «Хранилище защищено от очистки: да/нет» (`persisted()`).
- Статистика: книг всего / прочитано / читаю / минут прочитано (по `readingMs`).
- Помощь: «Как добавить книгу из Claude», «Как установить на iPhone» (Safari → Поделиться → На экран «Домой»), «Скилл для Claude» (что это и где лежит).
- О приложении: версия, «Обновить приложение», если ждёт новая версия.

Ключи `settings`: `theme` ('auto'|'light'|'sepia'|'dark'), `font` ('serif'|'sans'), `fontSize` (15–24), `lineHeight` ('tight'|'normal'|'loose'), `hyphens` (bool), `keepAwake` (bool), `wpm` (120–300), `sort`, `lastBackupAt`, `backupBannerHiddenUntil`, `booksAtLastBackup`.

## 11. Внешний вид

Сохраняем узнаваемый стиль старого приложения: «читальный зал» — бумажный фон, зелёный акцент, латунь для отметок и избранного, карточки каталога с шифром. Значит:
- Цвета (CSS-переменные на `:root`, темы через `[data-theme]`):
  - светлая: `--paper #F2F4F1, --surface #FFFFFF, --ink #15201B, --muted #58665F, --line #D6DED9, --accent #1C694C, --accent-ink #FFFFFF, --accent-soft #E1EFE8, --brass #946A15, --brass-soft #F4E9CE`;
  - тёмная: `--paper #0E1412, --surface #161F1B, --ink #E4EBE7, --muted #97A59F, --line #27322D, --accent #5CC29B, --accent-ink #07110D, --accent-soft #1A2B24, --brass #D7AB52, --brass-soft #2D2716`;
  - «Бумага» (сепия): подобрать в той же логике (тёплый кремовый фон, тёмно-коричневый текст). Контраст текста ≥ 4.5:1 и для `--muted` тоже — проверить.
- Шрифты: Literata — текст книг и названия; Golos Text — интерфейс; Unbounded — только знак «Kisr Library» и мелкие заголовки-надписи.
- Мобильная база (обязательно): `viewport-fit=cover` и `env(safe-area-inset-*)`, `100dvh`, поля ввода ≥ 16px, `-webkit-tap-highlight-color: transparent`, `:hover` только внутри `@media (hover: hover) and (pointer: fine)`, обратная связь на `:active`, `touch-action: manipulation` на кнопках, `user-select: none` только на элементах управления (не на тексте), `overscroll-behavior: contain` у шторок, `theme-color` для светлой и тёмной схем, обновление `theme-color` из JS при смене темы. Зум не запрещать.
- Доступность: зоны нажатия ≥ 44px, фокус в шторках удерживается и возвращается, `aria-label` по-русски, `prefers-reduced-motion`, контраст AA во всех темах.
- Иконки: штриховые SVG (можно взять набор `ICONS` из старого приложения). Иконка приложения: зелёный квадрат `#1C694C` с бумажно-светлым знаком (книга или «K»), размеры 192, 512, maskable 512, apple-touch 180.

## 13. Перенос из старого приложения

- Источники (оба локальные, оба в `.gitignore`):
  - **`kisr-library/`** — выгрузка, которую владелец сделал сам 22.11.2026: `data/library.json` (23 книги: `id, title, category, tags, summary, source, created, private, sections: [{title, md}]`; уже почищена — убраны 3 пустых раздела «Часть …») и `data/user-state.json` (`reading: [{articleId, order, key, max, pin?, done?, act?, at}]`, `prefs`, пустые `favorites`/`notes`/`tasks_done`). Это **главный источник текстов**.
  - **`migration/raw/`** — снимок базы артефакта (`articles`, `sections`, `data/users/me`: `pa-*`/`ps-*`, `r-*`, `prefs`, `bk-*`). Из него берётся прогресс (`r-*`) и `createdAt`/`updatedAt` книг. `bk-*` не переносим.
- Прогресс = объединение `user-state.json → reading` и `r-*`, по каждой книге побеждает бо́льший `at`. Перед выдачей файла владельцу снимок `migration/raw/data/users/me` обновляется свежей выгрузкой через `ArtifactData`: владелец продолжает читать в старом приложении.
- Скрипт `scripts/migrate-from-artifact.ts` создаёт `migration/kisr-library-backup-migrated.json` в формате §10.6:
  - книги — 23 (из них 2 личные, `private: true`), главы из `sections` по порядку; `origin: 'migration'`; слова, карточки и задачи пересчитываются функциями `src/core`; `createdAt`/`updatedAt` — из `migration/raw/articles`, а если их нет — из `created`; `addedAt` = время миграции;
  - прогресс: `chapter = order`, `maxChapter = max`, `blockKey = key`, `status = done ? 'finished' : 'reading'`, `lastReadAt = at`; `percent`/`wordsRead` считаются как «слова глав до текущей»; `pin: true` превращается в `favorite: true`; `act` становится `action`, если не пустое. Если глава с номером `order` в почищенной книге называется иначе, чем в `migration/raw/sections`, глава ищется по названию;
  - настройки: `fontSize = prefs.size` (18), тема `auto`.
- Скрипт печатает сводку (книг, глав, слов, прогрессов) и проверяет, что в результате нет пустых глав.
- Доставка на телефон: владелец пересылает файл себе (Telegram/почта/iCloud), открывает в установленном приложении «Ещё → Восстановить из копии». Файл в репозиторий не попадает.
